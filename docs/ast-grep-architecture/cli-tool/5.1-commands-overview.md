For detailed documentation on individual commands, see the respective pages: [Run Command](/ast-grep/ast-grep/5.2-run-command), [Scan Command](/ast-grep/ast-grep/5.3-scan-command), [New Command](/ast-grep/ast-grep/5.4-new-command), [Output Formatting](/ast-grep/ast-grep/5.5-output-formatting), and [Interactive Mode](/ast-grep/ast-grep/5.6-interactive-mode).

## Command-Line Interface Architecture

The ast-grep CLI is built using the `clap` library and implements a subcommand-based interface. The entry point at [crates/cli/src/main.rs6-8](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/main.rs#L6-L8) calls `execute_main()`, which dispatches to individual command handlers based on parsed arguments.

**Sources:** [crates/cli/src/main.rs1-9](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/main.rs#L1-L9) [crates/cli/src/lib.rs68-146](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L68-L146)

## Command Definitions

The CLI commands are defined through the `Commands` enum at [crates/cli/src/lib.rs49-66](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L49-L66) which contains variants for each subcommand. The `App` struct at [crates/cli/src/lib.rs41-47](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L41-L47) defines the top-level CLI structure.

| Command | Purpose | Handler Function | Requires Project |
| --- | --- | --- | --- |
| `run` | Ad-hoc pattern-based search and rewrite | `run_with_pattern()` | Optional |
| `scan` | Rule-based code analysis and fixes | `run_with_config()` | Yes* |
| `test` | Verify rule correctness with test cases | `run_test_rule()` | Yes |
| `new` | Scaffold new projects, rules, or tests | `run_create_new()` | Yes |
| `lsp` | Start Language Server Protocol backend | `run_language_server()` | Yes |
| `completions` | Generate shell completion scripts | `run_shell_completion()` | No |

\*The `scan` command can operate without a project when using `--rule` or `--inline-rules` options.

**Sources:** [crates/cli/src/lib.rs49-66](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L49-L66) [crates/cli/src/lib.rs136-146](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L136-L146)

## Global Options

The ast-grep CLI supports global options that can be specified before any subcommand. These are defined in the `App` struct at [crates/cli/src/lib.rs41-47](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L41-L47)

| Option | Short | Description |
| --- | --- | --- |
| `--config` | `-c` | Path to ast-grep root config (default: `sgconfig.yml`) |
| `--version` | `-V` | Display version information |
| `--help` | `-h` | Show help information |

The `--config` option is processed early in [crates/cli/src/lib.rs102-123](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L102-L123) by `setup_project_is_possible()`, which loads the `ProjectConfig` before command parsing. This allows custom language configurations to be available during argument validation.

**Sources:** [crates/cli/src/lib.rs44-46](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L44-L46) [crates/cli/src/lib.rs102-123](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L102-L123)

## Default Command Behavior

The CLI implements special logic to make `run` the default command when no subcommand is explicitly specified. The function `try_default_run()` at [crates/cli/src/lib.rs88-99](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L88-L99) detects when the user provides a `--pattern` (or `-p`) flag as the first argument without specifying a subcommand.

This enables the shorthand syntax:

```bash
sg -p 'pattern'      # Equivalent to: sg run -p 'pattern'
sg -p 'pattern' -l js # Equivalent to: sg run -p 'pattern' -l js
```

**Sources:** [crates/cli/src/lib.rs88-99](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L88-L99) [crates/cli/src/lib.rs131-132](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/lib.rs#L131-L132)

## Worker Pattern Architecture

The `run` and `scan` commands share a common execution pattern through the `Worker`, `PathWorker`, and `StdInWorker` traits. This abstraction enables consistent file processing across different command types.

| Worker Type | Use Case | Commands |
| --- | --- | --- |
| `RunWithSpecificLang` | Files with explicit `--lang` | `run` |
| `RunWithInferredLang` | Files with language detection | `run` |
| `ScanWithConfig` | Files with rule collection | `scan` |
| `ScanStdin` | Stdin with rule collection | `scan` |

**Sources:** [crates/cli/src/run.rs260-344](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L260-L344) [crates/cli/src/run.rs187-258](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L187-L258) [crates/cli/src/scan.rs129-286](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L129-L286) [crates/cli/src/scan.rs288-374](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L288-L374)

## Command Execution Flow

Each command follows a consistent execution pattern, though the specific implementation varies based on whether processing occurs on files or stdin, and whether a specific language is provided or inferred.

### Run Command Flow

The `run` command at [crates/cli/src/run.rs151-174](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L151-L174) handles three scenarios:

1.  **Stdin with specific language**: `RunWithSpecificLang::run_std_in()`
2.  **Files with specific language**: `RunWithSpecificLang::run_path()`
3.  **Files with inferred language**: `RunWithInferredLang::run_path()`

The command builds a `Pattern` from the provided pattern string at [crates/cli/src/run.rs121-133](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L121-L133) and optionally a `Fixer` for rewrites at [crates/cli/src/run.rs273-277](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L273-L277)

**Sources:** [crates/cli/src/run.rs151-185](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L151-L185) [crates/cli/src/run.rs260-369](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L260-L369)

### Scan Command Flow

The `scan` command at [crates/cli/src/scan.rs85-112](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L85-L112) handles rule-based analysis. It supports three rule sources:

1.  **Single rule file**: `--rule` option loads from a YAML file
2.  **Inline rules**: `--inline-rules` option parses YAML from command-line string
3.  **Project rules**: Loads from `sgconfig.yml` rule directories

The command builds a `RuleCollection` at [crates/cli/src/scan.rs140-157](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L140-L157) and processes files using the `ScanWithConfig` or `ScanStdin` workers.

**Sources:** [crates/cli/src/scan.rs85-127](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L85-L127) [crates/cli/src/scan.rs139-174](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L139-L174)

## Printer Selection

Both `run` and `scan` commands select appropriate printers based on output options. The printer determines the output format and is selected before the worker processes files.

| Condition | Printer | Description |
| --- | --- | --- |
| `--files-with-matches` | `FileNamePrinter` | Output matching file paths only |
| `--json` | `JSONPrinter` | Structured JSON output |
| `--interactive` or `--update-all` | `InteractivePrinter` | Interactive apply/reject mode |
| Default | `ColoredPrinter` | Colored terminal output |

**Sources:** [crates/cli/src/run.rs152-174](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L152-L174) [crates/cli/src/scan.rs86-112](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L86-L112)

## Command Argument Structures

Each command defines its own argument structure using `clap` derive macros:

-   **RunArg** [crates/cli/src/run.rs61-118](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L61-L118): Pattern, language, rewrite, strictness, selector, debug options
-   **ScanArg** [crates/cli/src/scan.rs26-76](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L26-L76): Rule source, format, severity overrides, max results
-   **TestArg**: Test discovery and execution options
-   **NewArg**: Scaffolding target and base directory
-   **LspArg**: Language server configuration
-   **CompletionsArg**: Shell type for completion generation

All command argument structures include embedded `InputArgs`, `OutputArgs`, and `ContextArgs` for consistent option handling across commands.

**Sources:** [crates/cli/src/run.rs61-118](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L61-L118) [crates/cli/src/scan.rs26-76](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L26-L76)

## Exit Code Handling

Commands return `Result<ExitCode>` to indicate success or failure:

-   **Success (0)**: Operation completed successfully
-   **Success with no matches (1)**: For `run` command when pattern finds no matches
-   **Error**: Command returns `Err(anyhow::Error)` which is converted to an appropriate exit code

The `run` command explicitly uses exit code 1 when no matches are found at [crates/cli/src/run.rs206](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L206-L206) and [crates/cli/src/run.rs304](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/run.rs#L304-L304) while the `scan` command returns an error for diagnostics of severity `Error` at [crates/cli/src/scan.rs188-192](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/scan.rs#L188-L192)
