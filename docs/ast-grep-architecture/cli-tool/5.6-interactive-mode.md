The Interactive Mode provides a terminal-based user interface for reviewing and selectively applying code transformations. It displays each match or diff to the user and prompts for acceptance, rejection, or editing before applying changes to files. For non-interactive output formats, see [Output Formatting](/ast-grep/ast-grep/5.4-new-command).

Sources: [crates/cli/src/print/interactive_print.rs1-129](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L1-L129)

## Architecture Overview

The `InteractivePrinter` wraps the `ColoredPrinter` to provide interactive user prompts on top of formatted output. It implements the `Printer` trait alongside other output formatters.

```rust
struct InteractivePrinter<P: Printer> {

    accept_all: bool,            // Auto-accept mode
    from_stdin: bool,            // Stdin processing mode

}
```

## Interactive Workflow State Machine

The interactive mode operates as a state machine that processes each match or diff, prompting the user for action and transitioning based on their response.

```

│                    Interactive Workflow                       │
├──────────────────────────────────────────────────────────────┤
│  Start                                                        │
│    │                                                          │
│    ▼                                                          │
│  ┌─────────────────┐                                         │
│  │ Get Next Item   │                                         │
│  └────────┬────────┘                                         │
│           │                                                   │
│           ▼                                                   │
│  ┌─────────────────┐     No      ┌──────────────────┐       │
│  │ Has More Items? ├────────────►│ after_print()     │       │
│  └────────┬────────┘             │ Show committed N  │       │
│           │ Yes                   └──────────────────┘       │
│           ▼                                                   │
│  ┌─────────────────┐                                         │
│  │ Display Item    │                                         │
│  │ (Highlights/    │                                         │
│  │  Diffs)         │                                         │
│  └────────┬────────┘                                         │
│           │                                                   │
│           ▼                                                   │
│  ┌─────────────────┐                                         │

│  │ y/n/a/q/e/Tab   │                                         │

│     ┌─────┴─────┬─────────┬─────────┐                        │
```

## User Controls and Prompts

The interactive mode provides different prompt interfaces depending on whether the user is viewing matches (read-only) or diffs (editable changes).

### Edit Prompt

When viewing diffs that can be applied, the user sees the edit prompt:

| Key | Action | Description |
| --- | --- | --- |
| `y` or `Enter` | Accept | Apply current change and continue |
| `n` | Reject | Skip current change |
| `a` | Accept All | Apply current and all remaining changes without prompting |
| `q` | Quit | Exit interactive mode immediately |
| `e` | Edit | Open file in `$EDITOR` at match location |
| `Tab` | Switch Fix | Cycle through multiple fixes for the same match |

The edit prompt is displayed via `prompt_edit()` at [crates/cli/src/print/interactive_print.rs39-45](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L39-L45)

### View Prompt

When viewing matches without fixes (search results), the user sees the view prompt:

| Key | Action | Description |
| --- | --- | --- |
| `Enter` | Next | Continue to next match |
| `q` | Quit | Exit interactive mode |
| `e` | Edit | Open file in editor |

The view prompt is displayed via `prompt_view()` at [crates/cli/src/print/interactive_print.rs47-53](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L47-L53)

### Highlights Payload

`Highlights` contains read-only match results for display:


This is created when `print_rule()` or `print_matches()` is called without fix operations. The payload includes the first line number to enable jumping to the correct location when opening in an editor.

### Diffs Payload

`Diffs` contains editable changes that can be applied:

```rust
struct InteractiveDiff {
    replacement: String,       // New text to insert
    range: Range<usize>,       // Byte range to replace
    first_line: usize,         // Line number for editor
    title: Option<String>,     // Fix description
    display: Vec<u8>,          // Rendered output for this fix
}
```

Each `InteractiveDiff` encapsulates:

-   `replacement`: New text to insert
-   `range`: Byte range to replace
-   `first_line`: Line number for editor positioning
-   `title`: Optional fix description
-   `display`: Rendered output for the specific fix

## Editor Integration

The interactive mode can launch an external text editor to allow direct file editing at the match location.

```rust
fn open_in_editor(path: &Path, line: usize) -> Result<()> {
    let editor = env::var("EDITOR").unwrap_or_else(|_| "vim".to_string());
    Command::new(editor)
        .arg(path)
        .arg(format!("+{}", line + 1))  // 1-based line number
        .status()?;
    Ok(())
}
```

The editor is launched with a line number argument (e.g., `vim +123 file.rs`) to position the cursor at the match location. The line number is 1-based, converted from the 0-based `first_line` field at [crates/cli/src/print/interactive_print.rs396](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L396-L396)

## File Rewriting Mechanism

The `apply_rewrite()` function reconstructs the modified file content by splicing replacements into the original source.

```rust
fn apply_rewrite(path: &Path, diffs: &[InteractiveDiff]) -> Result<()> {
    let original = fs::read_to_string(path)?;
    let mut result = String::new();
    let mut last_end = 0;
    
    for diff in diffs {
        result.push_str(&original[last_end..diff.range.start]);
        result.push_str(&diff.replacement);
        last_end = diff.range.end;
    }
    result.push_str(&original[last_end..]);
    
    fs::write(path, result)?;
    Ok(())
}
```

The algorithm at [crates/cli/src/print/interactive_print.rs374-388](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L374-L388) ensures that:

1.  Only confirmed diffs are applied (overlapping diffs are filtered earlier at [crates/cli/src/print/interactive_print.rs286-292](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L286-L292))
2.  Unchanged portions between diffs are preserved
3.  Trailing content after the last diff is appended

## Stdin Handling and Accept-All Mode

The interactive printer has special handling for non-interactive scenarios.

### Accept-All Mode

When `accept_all` is `true`, the printer automatically accepts all changes without prompting:

-   `prompt_edit()` immediately returns `'a'` at [crates/cli/src/print/interactive_print.rs40-42](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L40-L42)
-   `prompt_view()` immediately returns `'\n'` at [crates/cli/src/print/interactive_print.rs48-50](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L48-L50)
-   Highlights are not displayed at [crates/cli/src/print/interactive_print.rs75-77](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L75-L77)
-   The first diff in multiple-fix scenarios is always selected at [crates/cli/src/print/interactive_print.rs332-335](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L332-L335)

This mode is typically activated with the `-U` or `--update-all` CLI flag.

### Stdin Processing

When processing input from stdin (`from_stdin == true`):

| Condition | Behavior |
| --- | --- |
| `accept_all == false` | Error: `EC::StdInIsNotInteractive` at construction |
| `accept_all == true` | Rewritten content is printed to stdout instead of overwriting files |

The rationale is that interactive prompting is incompatible with piped input, and stdout output allows piping rewritten content to other commands.

## Alternate Screen Usage

All interactive prompts use `run_in_alternate_screen()` to prevent cluttering the user's terminal with temporary UI elements.

```rust
fn run_in_alternate_screen<T>(f: impl FnOnce() -> T) -> T {
    // Enter alternate screen buffer
    // Execute callback
    // Restore main screen buffer
}
```
