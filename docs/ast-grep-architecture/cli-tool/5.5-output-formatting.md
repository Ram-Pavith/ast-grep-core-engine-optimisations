This document covers the output formatting system in ast-grep's CLI tool, which handles presentation of search results, rule matches, and code diffs across multiple output formats. The system provides a unified interface for rendering AST matches and transformations in formats ranging from colored terminal output to structured JSON.

For information about rule-based analysis that generates the data being formatted, see [Rule System](/ast-grep/ast-grep/4-language-support). For CLI command processing that orchestrates the formatting, see [Commands and Arguments](/ast-grep/ast-grep/3.1-rule-configuration-format).

## Architecture Overview

The output formatting system is built around the `Printer` and `PrintProcessor` traits defined in [crates/cli/src/print/mod.rs43-62](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/mod.rs#L43-L62) This design separates data transformation (processor) from output management (printer), enabling parallel processing in worker threads while maintaining coordinated output.

**Core Trait Architecture**

| Printer | Processor | Buffer Type | Use Case |
| --- | --- | --- | --- |
| `ColoredPrinter` | `ColoredProcessor` | `termcolor::Buffer` | Terminal output |
| `JSONPrinter` | `JSONProcessor` | `Vec<u8>` | Structured output |
| `InteractivePrinter` | `InteractiveProcessor` | Wrapped buffer | User interaction |
| `CloudPrinter` | `CloudProcessor` | `Vec<u8>` | CI/CD integration |

*Sources: [crates/cli/src/print/mod.rs43-62](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/mod.rs#L43-L62) [crates/cli/src/print/colored_print.rs58-127](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L58-L127) [crates/cli/src/print/json_print.rs281-371](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L281-L371) [crates/cli/src/print/interactive_print.rs100-125](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/interactive_print.rs#L100-L125) [crates/cli/src/print/cloud_print.rs34-46](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/cloud_print.rs#L34-L46)*

**Processing Pipeline with Buffer Types**

The `PrintProcessor` trait defines four methods that transform match data into format-specific buffers. Each printer implementation uses a specific buffer type: `ColoredPrinter` uses `codespan_reporting::term::termcolor::Buffer`, `JSONPrinter` uses `Vec<u8>`, and `InteractivePrinter` wraps another printer's buffer type in `InteractivePayload`.

*Sources: [crates/cli/src/print/mod.rs27-41](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/mod.rs#L27-L41) [crates/cli/src/print/colored_print.rs106-127](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L106-L127) [crates/cli/src/print/json_print.rs318-371](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L318-L371)*

The trait methods process different input types:

| Method | Input | Output Purpose |
| --- | --- | --- |
| `print_rule()` | `Vec<NodeMatch>`, `SimpleFile`, `RuleConfig` | Format rule-based matches with diagnostics |
| `print_matches()` | `Vec<NodeMatch>`, `&Path` | Format pattern-only matches |
| `print_diffs()` | `Vec<Diff>`, `&Path` | Format pattern-based code changes |
| `print_rule_diffs()` | `Vec<(Diff, &RuleConfig)>`, `&Path` | Format rule-based fixes with metadata |

*Sources: [crates/cli/src/print/mod.rs27-41](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/mod.rs#L27-L41)*

## Output Formats

### Colored Terminal Output

The `ColoredPrinter<W: WriteColor>` struct at [crates/cli/src/print/colored_print.rs58-104](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L58-L104) provides terminal output using the `codespan-reporting` crate for diagnostic formatting. It wraps a `WriteColor` writer (typically `StandardStream`) and delegates processing to `ColoredProcessor`.

**ColoredPrinter Configuration**

| Field | Type | Purpose |
| --- | --- | --- |
| `writer` | `W: WriteColor` | Output destination |
| `style` | `ReportStyle` | Display format (rich/medium/short) |
| `heading` | `Heading` | File path display mode |
| `color` | `ColorChoice` | Color output control |
| `context` | `Context` | Context lines before/after matches |

*Sources: [crates/cli/src/print/colored_print.rs58-104](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L58-L104)*

The `ReportStyle` enum at [crates/cli/src/print/colored_print.rs27-35](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L27-L35) maps to `codespan_reporting::term::DisplayStyle`:

-   **Rich** (`DisplayStyle::Rich`): Full diagnostic with source previews, multi-line context
-   **Medium** (`DisplayStyle::Medium`): Line number, severity, message, and notes
-   **Short** (`DisplayStyle::Short`): Minimal output with line number, severity, message only

The `Heading` enum at [crates/cli/src/print/colored_print.rs37-56](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L37-L56) controls file path display:

-   **Auto**: Print heading for TTY output (detected via `atty::is(atty::Stream::Stdout)`)
-   **Always**: Print heading unconditionally
-   **Never**: Suppress heading (suitable for grep-style output)

**Diff Formatting**

The `DiffStyles` struct provides unified diff output using the `similar` crate. For rule diffs, `print_rule_diffs()` at [crates/cli/src/print/colored_print.rs251-304](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/colored_print.rs#L251-L304) prints rule metadata before the diff:

```rust
fn print_rule_diffs(&self, diffs: Vec<(Diff, &RuleConfig)>, path: &Path) {
    for (diff, rule) in diffs {
        print_rule_header(rule);  // severity[id]: message
        print_diff(&diff);        // unified diff
    }
}
```

### JSON Output

The `JSONPrinter<W: Write>` struct at [crates/cli/src/print/json_print.rs281-316](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L281-L316) generates structured JSON using `serde_json`. The `JSONProcessor` at [crates/cli/src/print/json_print.rs373-411](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L373-L411) transforms matches into serializable structures.

**JSON Data Structures**

| Structure | Fields | Purpose |
| --- | --- | --- |
| `MatchNode` | `text`, `range`, `file`, `lines` | Single match representation |
| `Pos` | `line`, `column` | Position within file |
| `Range` | `byteOffset`, `start`, `end` | Match span information |
| `MetaVariables` | `single`, `multi`, `transformed` | Captured pattern variables |

*Sources: [crates/cli/src/print/json_print.rs20-88](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L20-L88) [crates/cli/src/print/json_print.rs210-264](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L210-L264)*

**Context Lines and Character Counts**

The `CharCount` struct at [crates/cli/src/print/json_print.rs58-63](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/json_print.rs#L58-L63) provides `leading` and `trailing` character counts. Combined with the `lines` field, plugin authors can reconstruct the exact match position within displayed text:


This enables syntax highlighting or range extraction without re-parsing.

## Processing Pipeline

The formatting system processes different types of input data through specialized methods, each optimized for specific use cases:

| Method | Called By | Input | Output |
| --- | --- | --- | --- |
| `print_rule()` | scan command | Rule matches | Diagnostics with severity |
| `print_matches()` | run command | Pattern matches | Simple match output |
| `print_diffs()` | run --rewrite | Pattern diffs | Unified diff output |
| `print_rule_diffs()` | scan (with fixes) | Rule fixes | Diffs with rule metadata |

*Sources: [crates/cli/src/print/mod.rs27-41](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/print/mod.rs#L27-L41)*
