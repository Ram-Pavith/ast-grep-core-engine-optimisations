The `new` command provides scaffolding functionality for creating ast-grep projects, rules, test cases, and utility rules. This command automates the creation of properly structured YAML files and directory layouts, supporting both interactive prompts and command-line argument modes.

For information about running tests on created rules, see [Testing Rules](/ast-grep/ast-grep/3.4-testing-rules). For details on the project configuration structure, see [Project Configuration](/ast-grep/ast-grep/3.5-project-configuration).

## Purpose and Scope

The `new` command serves as a project initialization and content scaffolding tool. It handles:

-   Creating new ast-grep projects with proper directory structure and `sgconfig.yml`
-   Generating rule files in configured rule directories
-   Creating test case files in configured test directories
-   Generating utility rules in configured utility directories

The command supports both interactive mode (prompting users for input) and non-interactive mode (using command-line arguments with the `--yes` flag).

**Sources:** [crates/cli/src/new.rs1-425](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L1-L425)

## Command Structure

The `new` command is defined by the `NewArg` structure and accepts an optional subcommand specifying the entity type to create.

### Command Arguments

| Argument | Type | Description | Global |
| --- | --- | --- | --- |
| `entity` | Subcommand | The item type to create (project/rule/test/util) | No |
| `name` | String | The identifier of the item to create | Yes |
| `--lang, -l` | SgLang | The language for the rule/util (required for rule/util) | Yes |
| `--yes, -y` | Flag | Accept all defaults without interactive input | Yes |

The `NewArg` struct is defined at [crates/cli/src/new.rs14-33](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L14-L33) providing command-line argument parsing via clap.

**Sources:** [crates/cli/src/new.rs14-33](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L14-L33)

## Entity Types

The command supports four entity types, defined in the `Entity` enum:

## Interactive Mode

When the `--yes` flag is not provided, the command enters interactive mode using the `inquire` library for user prompts.

### Interactive Methods

The `NewArg` implementation provides several interactive helper methods:

| Method | Purpose | Default Behavior with `--yes` |
| --- | --- | --- |
| `ask_dir()` | Prompt for directory name | Uses provided default |
| `confirm()` | Ask yes/no question | Returns `true` |
| `ask_entity_type()` | Select entity type | Returns error if not provided |
| `choose_language()` | Select language | Returns error if not provided |
| `ask_name()` | Enter item name | Returns error if not provided |

These methods are defined at [crates/cli/src/new.rs46-101](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L46-L101)

### Interactive Workflow Example

For rule creation, the interactive flow is:

1.  Ask for rule name (if not provided)
2.  Select target rule directory (if multiple configured)
3.  Choose programming language
4.  Confirm whether to create accompanying test

This is implemented in `create_new_rule()` at [crates/cli/src/new.rs247-275](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L247-L275)

## Project Creation

### Directory Structure

When creating a new project, the command generates the following structure:

```
my-project/
├── sgconfig.yml
├── rules/
│   └── .gitkeep
├── rule-tests/     (optional)
│   └── .gitkeep
└── utils/          (optional)
    └── .gitkeep
```

The `create_new_project()` function at [crates/cli/src/new.rs198-230](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L198-L230) orchestrates project creation:

1.  Creates `rules/` directory (mandatory)
2.  Optionally creates `rule-tests/` directory if user confirms
3.  Optionally creates `utils/` directory if user confirms
4.  Generates `sgconfig.yml` with `AstGrepConfig` structure
5.  Adds `.gitkeep` files to maintain empty directories in version control

Each directory is created using `create_dir()` at [crates/cli/src/new.rs35-43](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L35-L43) which ensures the directory exists and adds a `.gitkeep` file to address issue #1273.

## Rule Creation

### Rule File Template

Rules are created using the `default_rule()` template at [crates/cli/src/new.rs232-245](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L232-L245):

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/ast-grep/ast-grep/main/schemas/rule.json
id: ${name}
message: Add your message here
severity: error
language: ${lang}
rule:
  pattern: PATTERN
# utils:
# note:
```

The template includes:

-   JSON schema reference for IDE validation
-   Placeholder message and pattern
-   Comments for optional fields (`utils`, `note`)
-   Default severity of `error`

### Rule Creation Process

The implementation is at [crates/cli/src/new.rs247-275](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L247-L275) Key steps:

1.  Prompt for rule name via `ask_name()`
2.  Select destination directory if multiple `rule_dirs` configured
3.  Check for existing file and error if present
4.  Prompt for language selection
5.  Write template file using `default_rule()`
6.  Optionally create accompanying test case

**Sources:** [crates/cli/src/new.rs232-245](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L232-L245) [crates/cli/src/new.rs247-275](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L247-L275)

## Test Creation

### Test File Template

Test cases are created using the `default_test()` template at [crates/cli/src/new.rs277-286](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L277-L286):

```yaml
id: ${name}
valid:
  - VALID_CODE
invalid:
  - INVALID_CODE
```

The template provides:

-   Rule ID matching the rule to test
-   Placeholder arrays for valid and invalid test cases
-   Minimal structure following the test format documented in [Testing Rules](/ast-grep/ast-grep/3.4-testing-rules)

### Test Creation Logic

The `create_new_test()` function at [crates/cli/src/new.rs288-319](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L288-L319) handles test file creation:

1.  Validates that `test_configs` is configured (returns `NoTestDirConfigured` error otherwise)
2.  Selects test directory from configured options (prompts if multiple)
3.  Prompts for rule ID if not provided
4.  Creates file at `{test_dir}/{name}-test.yml`
5.  Writes template using `default_test()`

This function is also called automatically when creating a rule if the user confirms test creation.

**Sources:** [crates/cli/src/new.rs277-286](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L277-L286) [crates/cli/src/new.rs288-319](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L288-L319)

## Utility Rule Creation

### Utility Template

Utility rules use the `default_util()` template at [crates/cli/src/new.rs321-329](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L321-L329):

```yaml
id: ${name}
language: ${lang}
rule:
  pattern: PATTERN
```

Utility rules differ from regular rules in that they:

-   Omit `message` and `severity` fields (not user-facing)
-   Are referenced by other rules via the `utils` field
-   Are loaded into `GlobalRules` during configuration parsing

### Utility Creation Process

The `create_new_util()` function at [crates/cli/src/new.rs331-360](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L331-L360) follows a similar pattern to rule creation:

1.  Validates that `util_dirs` is configured
2.  Selects utility directory (prompts if multiple)
3.  Prompts for utility name and language
4.  Creates file at `{util_dir}/{name}.yml`
5.  Writes template using `default_util()`

Utilities are discovered and loaded by `find_util_rules()` in [crates/cli/src/config.rs133-162](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/config.rs#L133-L162) when the project configuration is initialized.

## Integration with ProjectConfig

The `new` command integrates tightly with `ProjectConfig` for non-project entity creation:

```rust
let project = ProjectConfig::setup()?;
// project contains rule_dirs, test_configs, util_dirs
```

The workflow:

1.  `ProjectConfig::setup()` at [crates/cli/src/config.rs96-109](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/config.rs#L96-L109) attempts to find `sgconfig.yml`
2.  If found, parses configuration and extracts directory paths
3.  Returns `ProjectConfig` with `rule_dirs`, `test_configs`, and `util_dirs`
4.  `new` command uses these paths to determine where to create files
5.  If not found and entity is `Project`, creates new configuration
6.  If not found and entity is not `Project`, returns error

The configuration discovery walks up the directory tree looking for `sgconfig.yml` or `sgconfig.yaml` as implemented in [crates/cli/src/config.rs266-285](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/config.rs#L266-L285)

**Sources:** [crates/cli/src/config.rs96-109](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/config.rs#L96-L109) [crates/cli/src/config.rs266-285](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/config.rs#L266-L285)

## Error Handling

The command handles several error conditions:

| Error Context | When Triggered | Error Type |
| --- | --- | --- |
| `ProjectNotExist` | No `sgconfig.yml` found when creating rule/test/util | `ErrorContext::ProjectNotExist` |
| `ProjectAlreadyExist` | Attempting to create project when `sgconfig.yml` exists | `ErrorContext::ProjectAlreadyExist` |
| `FileAlreadyExist` | Target file already exists | `ErrorContext::FileAlreadyExist(PathBuf)` |
| `NoTestDirConfigured` | No test directories in configuration | `ErrorContext::NoTestDirConfigured` |
| `NoUtilDirConfigured` | No utility directories in configuration | `ErrorContext::NoUtilDirConfigured` |
| `InsufficientCLIArgument` | Required argument missing with `--yes` flag | `ErrorContext::InsufficientCLIArgument(&str)` |

## Non-Interactive Mode

When the `--yes` flag is provided, the command requires all necessary arguments via command line and uses default values for directory names:

| Entity | Required Arguments | Default Directories |
| --- | --- | --- |
| Project | None | `rules/`, `rule-tests/`, `utils/` |
| Rule | `name`, `--lang` | First `rule_dir` from config |
| Test | `name` | First test directory from config |
| Util | `name`, `--lang` | First `util_dir` from config |

The `--yes` flag causes all confirmation prompts to return `true` automatically (see [crates/cli/src/new.rs55-60](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/cli/src/new.rs#L55-L60)) and causes selection prompts to use the first available option.
