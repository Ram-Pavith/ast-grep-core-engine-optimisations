This document provides a comprehensive reference for the `@ast-grep/napi` Node.js API, which exposes ast-grep's AST pattern matching capabilities to JavaScript and TypeScript applications. The API provides both synchronous and asynchronous methods for parsing source code, searching for patterns, and manipulating AST nodes.

For information about the NAPI package structure and platform-specific builds, see [NAPI Package Structure](/ast-grep/ast-grep/7.2-package-structure) and [Platform-Specific Builds](/ast-grep/ast-grep/7.3-async-operations). For the CLI tool, see [CLI Tool](/ast-grep/ast-grep/5-cli-tool). For Python bindings, see [Python Integration](/ast-grep/ast-grep/8-python-integration).

## API Architecture Overview

The NAPI API is organized into three main layers: top-level generic functions, language-specific modules, and core AST manipulation classes.

**Sources:** [crates/napi/src/lib.rs1-128](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L1-L128) [crates/napi/index.d.ts1-15](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/index.d.ts#L1-L15)

## Top-Level API Functions

### parse

Parses source code synchronously and returns an `SgRoot` instance representing the parsed AST. The `lang` parameter specifies the programming language (e.g., `"javascript"`, `"typescript"`, `"python"`).

**Implementation:** [crates/napi/src/lib.rs68-72](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L68-L72)

**Example Usage:** [crates/napi/__test__/index.spec.ts8](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/__test__/index.spec.ts#L8-L8)

### parseAsync

Parses source code asynchronously in a separate thread, allowing concurrent processing of multiple sources without blocking the main event loop. Returns a Promise that resolves to an `SgRoot` instance.

**Implementation:** [crates/napi/src/lib.rs80-83](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L80-L83) [crates/napi/src/find_files.rs17-34](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L17-L34)

**Example Usage:** [crates/napi/__test__/index.spec.ts21-33](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/__test__/index.spec.ts#L21-L33)

**Note:** Spawning excessive threads may degrade performance. Refer to libuv documentation for tuning recommendations.

### kind

Converts a node kind string name to its numeric identifier. Used for matching nodes by their syntactic type.

**Implementation:** [crates/napi/src/lib.rs86-91](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L86-L91)

**Example Usage:** [crates/napi/__test__/index.spec.ts145-152](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/__test__/index.spec.ts#L145-L152)

### pattern

Compiles a pattern string into a `NapiConfig` object that can be used for matching. This is a convenience function that wraps the pattern in a configuration object.

**Implementation:** [crates/napi/src/lib.rs94-105](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L94-L105)

### findInFiles

Discovers and parses multiple files in parallel, applying a matcher to each file and invoking the callback with matching nodes. Returns a Promise that resolves to the total number of files processed.

**Implementation:** [crates/napi/src/lib.rs112-119](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L112-L119) [crates/napi/src/find_files.rs164-186](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L164-L186)

**Example Usage:** [crates/napi/__test__/index.spec.ts230-248](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/__test__/index.spec.ts#L230-L248)

### parseFiles

Discovers and parses multiple files in parallel, invoking the callback with each parsed file's `SgRoot`. Returns a Promise that resolves to the total number of files parsed.

**Implementation:** [crates/napi/src/find_files.rs88-111](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L88-L111)

Registers custom tree-sitter language parsers at runtime, enabling support for languages not built into ast-grep.

## Language-Specific Modules

Each built-in language has a dedicated module that provides pre-configured versions of the core API functions. These modules eliminate the need to specify the language parameter.

### Module API

Each language module exports the following methods:

| Method | Signature | Description |
| --- | --- | --- |
| `parse` | `(src: string) => SgRoot` | Parse source code synchronously |
| `parseAsync` | `(src: string) => Promise<SgRoot>` | Parse source code asynchronously |
| `kind` | `(kindName: string) => number` | Get numeric kind identifier |
| `pattern` | `(pattern: string) => NapiConfig` | Create pattern matcher |
| `findInFiles` | `(config: FindConfig, callback: Function) => Promise<number>` | Search in multiple files |

**Implementation:** Language modules are generated via the `impl_lang_mod!` macro at [crates/napi/src/lib.rs21-53](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L21-L53) with concrete instances at [crates/napi/src/lib.rs60-65](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L60-L65)

**Example Usage:**

```typescript
import { js } from '@ast-grep/napi';

// No need to specify language
const sg = js.parse('const x = 1;');
```

**Sources:** [crates/napi/src/lib.rs21-65](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/lib.rs#L21-L65) [crates/napi/__test__/index.spec.ts3-4](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/__test__/index.spec.ts#L3-L4)

Methods for searching and validating nodes against patterns or rules.

| Method | Signature | Returns | Description |

## Asynchronous Operations

### Threading Model

The NAPI bindings expose two async operations that leverage Rust's thread pool to enable concurrent processing.

### parseAsync

The `parseAsync` function delegates parsing to a background thread, preventing the main event loop from blocking during expensive parse operations.

**Implementation:** The `ParseAsync` struct implements the `Task` trait at [crates/napi/src/find_files.rs17-34](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L17-L34) with `compute()` performing the actual parsing in a worker thread.

**Example Usage:**

```typescript
import { js } from '@ast-grep/napi';

// Parse multiple files concurrently
const results = await Promise.all([
  js.parseAsync('const a = 1'),
  js.parseAsync('const b = 2'),
]);
```

### findInFiles

The `findInFiles` function uses a parallel file walker to process multiple files concurrently, calling the provided callback for each file with matching nodes.

**Implementation:** The `IterateFiles` task at [crates/napi/src/find_files.rs38-73](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L38-L73) wraps an `ignore::WalkParallel` walker that spawns multiple threads to traverse the file system and parse files.

**File Processing Flow:**

1.  `WalkParallel` discovers files matching language globs
2.  Each worker thread parses a file and applies the matcher
3.  If matches are found, nodes are pinned to prevent dangling references
4.  The threadsafe function calls the JavaScript callback with matches
5.  Returns total file count when all files are processed

**Callback Invocation:** The callback is invoked via `ThreadsafeFunction` at [crates/napi/src/find_files.rs228](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L228-L228) which safely crosses the thread boundary from Rust to JavaScript.

**Example Pattern:**

```typescript
import { js } from '@ast-grep/napi';

await js.findInFiles(
  {
    paths: ['src/'],
    matcher: { rule: { pattern: 'console.log($MSG)' } },
  },
  (err, nodes) => {
    console.log(`Found ${nodes.length} matches`);
  }
);
```

**Sources:** [crates/napi/src/find_files.rs17-230](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/src/find_files.rs#L17-L230)

## Native Module Loading

The NAPI package uses platform-specific native bindings (`.node` files) compiled for each target architecture.

The loader at [crates/napi/index.js66-360](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/index.js#L66-L360) attempts to load native bindings in the following order:

1.  **Local package:** Tries `./ast-grep-napi.{platform}-{arch}.node` from the installed package
2.  **Scoped package:** Falls back to optional dependency `@ast-grep/napi-{platform}-{arch}`
3.  **WASI fallback:** Attempts to load WebAssembly version as last resort

**Platform Detection:**

-   For Linux, checks if the system uses musl libc via [crates/napi/index.js13-64](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/index.js#L13-L64)
-   Selects the appropriate binary based on `process.platform` and `process.arch`

**Error Handling:** If no native binding can be loaded, the loader throws an error with all accumulated load attempts at [crates/napi/index.js383-393](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/index.js#L383-L393)

## API Usage Patterns

### Basic Pattern Matching

```typescript
import { js } from '@ast-grep/napi';

const sg = js.parse('console.log("hello")');
const matches = sg.root().findAll('console.log($MSG)');
console.log(matches.length); // 1
```

### Multi-Pattern Search

```typescript
import { js } from '@ast-grep/napi';

const sg = js.parse('let a = 1; var b = 2;');
const root = sg.root();

const letMatches = root.findAll('let $VAR = $VAL');
const varMatches = root.findAll('var $VAR = $VAL');

console.log(letMatches[0].getMatch('VAR')?.text()); // 'a'
```

**Sources:** [crates/napi/__test__/index.spec.ts35-47](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/napi/__test__/index.spec.ts#L35-L47)

### Code Transformation

```typescript
import { js } from '@ast-grep/napi';

const sg = js.parse('var x = 1');
const root = sg.root();

const node = root.find('var $VAR = $VAL')!;
const edit = node.replace('let $VAR = $VAL');
const result = root.commitEdits([edit]);

console.log(result); // 'let x = 1'
```

### Relational Constraints

```typescript
import { js } from '@ast-grep/napi';

const sg = js.parse('function test() { console.log("x"); }');
const root = sg.root();

const config = {
  rule: { pattern: 'console.log($MSG)' },
  constraints: {
    inside: { pattern: 'function $NAME() { $$$BODY }' },
  },
};

const matches = root.findAll(config);
```
