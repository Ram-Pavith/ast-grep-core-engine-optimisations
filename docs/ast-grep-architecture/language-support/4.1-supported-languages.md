# Supported Languages

This page documents all programming languages supported by ast-grep, including their identifiers, aliases, file extensions, and configuration options. For information about how pattern syntax is adapted for different languages, see [Pattern Preprocessing](/ast-grep/ast-grep/4.2-pattern-preprocessing). For details on registering custom languages at runtime, see [Dynamic Language Loading](/ast-grep/ast-grep/4.3-dynamic-language-loading).

## Overview

ast-grep supports 26 programming languages through integration with tree-sitter parsers. Each language is represented as a variant in the `SupportLang` enum and can be identified by multiple aliases and file extensions. Languages are statically linked via Cargo feature flags, with conditional compilation allowing selective inclusion for reduced binary size in specialized deployments.

## Language Enumeration

The `SupportLang` enum defines all supported languages as a compile-time enumeration. This enum implements the `Language` and `LanguageExt` traits, providing a unified interface for language-specific operations.

**Definition and Traits**

The enum is defined at [crates/language/src/lib.rs254-283](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L254-L283):

```rust
pub enum SupportLang {
  Bash, C, Cpp, CSharp, Css, Go, Elixir, Haskell, Hcl, Html,
  Java, JavaScript, Json, Kotlin, Lua, Nix, Php, Python, Ruby,
  Rust, Scala, Solidity, Swift, Tsx, TypeScript, Yaml,
}
```

Each variant represents a distinct language and delegates method calls to the corresponding language-specific type (e.g., `SupportLang::Rust` delegates to the `Rust` struct). The delegation is implemented via the `execute_lang_method!` macro at [crates/language/src/lib.rs414-446](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L414-L446)

**Static Language List**

The `all_langs()` constant function at [crates/language/src/lib.rs286-292](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L286-L292) returns an array of all supported languages, used for iteration during language detection:

```rust
pub const fn all_langs() -> [SupportLang; 26] {
    [
        SupportLang::Bash,
        SupportLang::C,
        SupportLang::Cpp,
        // ... all languages
    ]
}
```

## Language Detection

ast-grep provides two primary mechanisms for identifying the target language:

**1. String-Based Detection (`FromStr`)**

The `FromStr` implementation at [crates/language/src/lib.rs400-412](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L400-L412) matches language names and aliases case-insensitively:

Examples:

- `"rust"`, `"rs"`, `"Rust"` all resolve to `SupportLang::Rust`
- `"javascript"`, `"js"`, `"jsx"` all resolve to `SupportLang::JavaScript`
- `"cpp"`, `"c++"`, `"cxx"` all resolve to `SupportLang::Cpp`

**2. Path-Based Detection (`from_path`)**

The `from_extension()` function at [crates/language/src/lib.rs522-528](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L522-L528) extracts the file extension and matches it against the `extensions()` arrays:

Examples:

- `"main.rs"` → `Some(SupportLang::Rust)`
- `"app.jsx"` → `Some(SupportLang::JavaScript)`
- `"config.yml"` → `Some(SupportLang::Yaml)`

**Alias Implementation**

Aliases are defined using the `impl_aliases!` macro at [crates/language/src/lib.rs370-397](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L370-L397) which generates:

- The `Alias` trait implementation with a static string array
- A `Deserialize` implementation for YAML/JSON parsing
- A `From<Lang>` conversion to `SupportLang`

*Sources: [crates/language/src/lib.rs149-198](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L149-L198) [crates/language/src/lib.rs370-412](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L370-L412) [crates/language/src/lib.rs522-528](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L522-L528)*

## Feature Flags and Conditional Compilation

ast-grep uses Cargo feature flags to control which language parsers are compiled into the binary. This allows specialized builds with reduced binary size.

**Feature Flag Architecture**

| Feature Flag | Purpose | Languages Included |
|--------------|---------|-------------------|
| `builtin-parser` | Default - all languages | All 26 languages |
| `napi-lang` | Node.js bindings subset | CSS, HTML, JavaScript, TypeScript |
| `tree-sitter-*` | Individual language | One specific language |

The WebAssembly deployment uses selective features to minimize bundle size, while the CLI tool uses the full `builtin-parser` feature set.

*Sources: [crates/language/Cargo.toml46-79](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/Cargo.toml#L46-L79) [crates/language/src/parsers.rs7-21](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/parsers.rs#L7-L21)*

**Feature Sets**

Three feature configurations are defined in [crates/language/Cargo.toml46-80](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/Cargo.toml#L46-L80):

1. **`default` feature**: Enables `builtin-parser`, including all 23 languages
2. **`builtin-parser` feature**: Explicit list of all tree-sitter parser dependencies
3. **`napi-lang` feature**: Subset for Node.js bindings (CSS, HTML, JavaScript, TypeScript)

**Conditional Parser Loading**

The `conditional_lang!` macro at [crates/language/src/parsers.rs7-21](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/parsers.rs#L7-L21) conditionally compiles parser access:

```rust
#[cfg(feature = "tree-sitter-rust")]
pub fn lang_rs() -> Language {
    tree_sitter_rust::LANGUAGE.into()
}

#[cfg(not(feature = "tree-sitter-rust"))]
pub fn lang_rs() -> Language {
    unimplemented!("Rust parser not compiled in")
}
```

When a feature is disabled, accessing that parser panics with an unimplemented error. This is used in WebAssembly builds where certain parsers cannot be compiled.

**Parser Dependencies**

Each language has a corresponding tree-sitter dependency in [crates/language/Cargo.toml20-44](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/Cargo.toml#L20-L44):

- Standard parsers: `tree-sitter-{lang} = { version = "...", optional = true }`
- Kotlin: Uses forked package `tree-sitter-kotlin-sg`
- TypeScript/TSX: Share `tree-sitter-typescript` with two exports (`LANGUAGE_TYPESCRIPT`, `LANGUAGE_TSX`)
- PHP: Uses `LANGUAGE_PHP_ONLY` export to exclude HTML parsing

*Sources: [crates/language/Cargo.toml20-80](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/Cargo.toml#L20-L80) [crates/language/src/parsers.rs1-111](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/parsers.rs#L1-L111)*

## Language Categories

Languages are divided into three categories based on their identifier syntax and how they handle the `$` character used in ast-grep's meta-variable syntax:

### Stub Languages

Stub languages accept `$` as a valid identifier character, so patterns like `$VAR` work natively without preprocessing. These are defined using the `impl_lang!` macro at [crates/language/src/lib.rs64-90](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L64-L90):

- **Bash**: Shell scripts where `$` denotes variables
- **Java**: `$` allowed in identifiers
- **JavaScript/JSX**: `$` commonly used (e.g., jQuery, template literals)
- **JSON**: No identifier restrictions
- **Lua**: `$` not reserved
- **Scala**: `$` allowed in identifiers
- **Solidity**: `$` permitted
- **TSX/TypeScript**: Same as JavaScript

Implementation:

```rust
impl_lang!(Js, "JavaScript", lang_js(), ["js", "jsx", "javascript"]);
```

### Expando Languages

Expando languages do not accept `$` in identifiers, requiring pattern preprocessing to replace `$VAR` with an alternative character before parsing. These are defined using the `impl_lang_expando!` macro at [crates/language/src/lib.rs115-147](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L115-L147):

The `expando_char()` method returns the replacement character:

- **𐀀** (U+10000): C, C++ - from Unicode Supplementary Multilingual Plane
- **µ** (U+00B5): CSharp, Elixir, Go, Haskell, Hcl, Kotlin, Php, Python, Ruby, Rust, Swift
- **_** (underscore): Css, Nix - for languages where Unicode may be restricted

Example implementation for Rust at [crates/language/src/lib.rs235](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L235-L235):

```rust
impl LanguageExt for Rust {
    fn expando_char(&self) -> char {
        'µ'
    }
}
```

The `pre_process_pattern()` function at [crates/language/src/lib.rs92-111](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L92-L111) performs the substitution. See [Pattern Preprocessing](/ast-grep/ast-grep/4.2-pattern-preprocessing) for details.

### Injectable Languages

Injectable languages can contain embedded code from other languages. Currently only HTML implements this:

- **HTML**: Can contain embedded JavaScript (in `<script>` tags) and CSS (in `<style>` tags)

The `extract_injections()` method at [crates/language/src/lib.rs474-483](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L474-L483) identifies embedded code ranges. See [Language Injection](/ast-grep/ast-grep/4.4-language-injection) for details.

## File Type Generation

Each language generates an `ignore::Types` structure for efficient file filtering during directory traversal. The `file_types()` method at [crates/language/src/lib.rs544-550](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L544-L550) creates a `TypesBuilder` with glob patterns for all file extensions:

```rust
fn file_types(&self) -> Result<ignore::Types> {
    let mut builder = TypesBuilder::new();
    for ext in self.extensions() {
        builder.add(self.to_string(), format!("*.{}", ext))?;
    }
    Ok(builder.build()?)
}
```

The `add_custom_file_type()` helper at [crates/language/src/lib.rs530-542](https://github.com/ast-grep/ast-grep/blob/3ae01aec/crates/language/src/lib.rs#L530-L542) converts each extension into a `*.ext` glob pattern and registers it with the builder. This integrates with the `ignore` crate used for fast parallel file walking in the CLI.

## Usage Examples

**Language Identification from String**

```rust
let lang: SupportLang = "rust".parse()?;  // From name
let lang: SupportLang = "rs".parse()?;     // From alias
let lang: SupportLang = "Python".parse()?; // Case insensitive
```

**Language Detection from File Path**

```rust
let lang = SupportLang::from_extension(Path::new("main.rs"))?;  // Rust
let lang = SupportLang::from_extension(Path::new("app.jsx"))?; // JavaScript
let lang = SupportLang::from_extension(Path::new("config.yml"))?; // YAML
```

**Accessing Language Properties**

```rust
let lang = SupportLang::Rust;
println!("Name: {}", lang.to_string());        // "Rust"
println!("Expando: {}", lang.expando_char());   // 'µ'
println!("Extensions: {:?}", lang.extensions()); // ["rs"]
```
